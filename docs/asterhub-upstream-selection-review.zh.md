# AsterHub 上游选择性更新审查

[English](asterhub-upstream-selection-review.md) | 中文

本轮比较 AsterHub 的 DSH 0.2.0-rc.2 基线与上游 0.2.1-alpha.1。仅回移植用户选定修复，项目版本保持原基线。

## 已移植范围

- Office：LibreOffice Kit 升级为 0.1.5，保留 ASAR 外的原生引擎资源解析，并兼容清单刷新。
- Desktop：默认端口改为操作系统分配，账户状态投影接受 no-response 错误码。
- 插件：安装/启用前刷新运行时包解析，停用/卸载后刷新；保留安装包映射及正在运行的模块。已加载包改目录或版本仍需重启。
- HMR：清单变化失效解析缓存，保留已执行模块和入口身份。为兼容此修复，同步移植 Loader 的入口重载条件修复及其 vendoring 记录。

## 模型选择修复

客户从当前登录 Key 的 /v1/models 目录选择模型和思考档。配置模型只作为描述模板，不进入可选列表；首次同步失败显示错误，账户切换清空缓存。选择可保存为后续会话默认值，但保存仍要求供应商固定且模型属于该账户目录。

测试账户现有 Key 全部属于 AsterHub 分组（ID 6），目录返回七个真实模型，不含 aster。未发起推理请求、创建或改动 Key。

## invariant 单独审查

上游删除注册表包、38 个包的 src/invariant.ts 配套检查、相应导出与测试，并改变四类通知监听器对 INVARIANT 错误的重新抛出行为。Invariant 检查用于检查会话日志、Agent 状态等内部一致性。

当前桌面默认组合未挂载这些插件；sdk-minimal 挂载五行。删除不会自动删除 AsterHub 的供应商锁、鉴权、凭据隔离或沙箱限制，但会破坏导入 invariant 子路径的第三方插件，并减少相应诊断与测试机制。

建议本轮保留。后续若升级整个核心版本，需要先审查外部插件导入和测试替代覆盖，再一起处理注册表、导出、SDK 组合及通知异常语义，避免零散删除。

## 排除范围

Schedule 默认组合、Claude Code Mods、publicUrl、release channel 与构建工具变更均未移植。定时任务仍遵循已有精选功能方向。

## 验证状态

受影响的 Host/Client TypeScript 项目图编译通过。模型列表、默认选择与下拉菜单回归已增加；定向测试结果记录于交接文档。Windows 文件 symlink 测试因本机缺少创建权限失败，不能视为通过。新便携构建及打包后的 Office 冒烟检查通过；最新压缩包与校验值见根目录交接文档。
