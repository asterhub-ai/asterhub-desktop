## 1. 项目背景与目标

AsterHub 的产品形态是**桌面端 AI 工作台**。此前以 Web 形态（`asterhub-ai/asterhub` 仓库）做功能验证；2026-09-27 决定桌面端底座采用 **DeepSeek Harness（DSH）的 fork**，原因是 DSH 的 provider 接入边界干净（统一走 `dsh-llm` 服务的 adapter 注册）、功能完整度高（会话/工作区/MCP/工具/审批齐全），整体采用 + 换认证层比在旧 Web 代码上重写桌面端代价小。

产品约束（决策依据）：

- **账户由 sub2api 托管验证**（注册/登录/充值都在 sub2api / xapi.fans），桌面端不做多用户、不做账户机制，本地只持有一条 sub2api 签发的模型 key。
- 模型池由我方在网关后台选型控制，兼容性在源头保证，客户端不做特殊适配。
- 工作台默认使用"标准模式"，不提供 Agent 预设切换与模型切换。

## 3. 技术栈与架构要点

| 层 | 技术 |
|---|---|
| 桌面壳 | Electron（apps/desktop），负责 Host 子进程生命周期、窗口、更新、外链 |
| Host | Node 子进程（apps/desktop-host + packages 组合），承载全部业务服务 |
| Web UI | React + Vite（apps/web），客户端插件按 `dsh.client` manifest 打包进模块表 |
| 服务组合 | Cordis 组合文件：`packages/bundle/base/cordis.patch.yml`（基线）+ `packages/bundle/web-app/cordis.patch.yml`（Web 桌面增量层） |
| 模型接入 | `dsh-llm` 统一服务 + adapter（`llm-pi-ai` 支持 OpenAI 兼容网关的自定义 route） |
| 远程调用 | Typert：宿主服务类 `extends TypertRemoteService` + `@Remote` 方法；构建期由 `packages/typert/generator` 生成 `lib/typert.host.js` / `lib/typert.remote-client.js`（package.json 需声明 `./typert`、`./remote` 导出） |
| 客户端槽位 | `ctx.slots`：槽在契约（`contract/slots.ts`）声明、注册方 `ctx.slots.inject(name, ...)` 挂占位者；跨包类型增强经 d.ts，注意打包丢增强的坑（见 §7） |
| 凭证 | `credentials-local`：`$DSH_HOME/.credentials.yaml`，优先级=环境变量 > 管理文件 > .env |

组合文件是理解本项目的钥匙：**哪些插件挂载、默认 provider/model、遥测开关，全在 cordis.patch.yml 里**。

## 4. 修改方向与决策记录

1. **认证替换 = 纯配置**。`llm-pi-ai` 原生支持 OpenAI 兼容网关的自定义 route，无需写 adapter：组合里挂 `providers.sub2api`（`api: openai-completions`、`baseURL` 默认 `https://xapi.fans/v1`、可被 `ASTERHUB_MODEL_BASE_URL` 覆盖），key 走 `SUB2API_API_KEY` 凭据引用。`llm-deepseek`、`web-search-deepseek`、`session-log-deepseek`、`plugin-package-inventory-deepseek`、`deepseek-llm-api-extensions`、OTel 遥测全部从默认组合移除。
2. **多用户/多账户隔离是伪命题（桌面场景）**。OS 账户才是安全边界；产品是一人多 sub2api 账户切换，真实隔离在网关侧按 key/额度天然成立。本地只存一条 key。
3. **Agent 预设取消**。web-app 组合卸载 `ui-agent-preset` 客户端插件；宿主 `agent-presets` 服务 `modeSelectionEnabled` 默认 false（关闭时宿主强制用部署默认预设，忽略历史用户选择——上游本就为此设计的语义）。恢复只需加回组合行并打开开关。
4. **插件入口与 DSH 官方生态解耦**。侧栏"插件"页与设置"插件"区都保留入口、替换为占位页；DSH 的安装/管理机制与宿主插件配置卡全部删除。`plugins.item`、`settings.plugins.tab` 等槽契约保留，自有插件功能在 `ui-plugin-manager` / `ui-settings-plugins` 两个包里实现。
5. **模型选择器移除**。web-app 组合卸载 `ui-model-selection`：固定使用部署默认模型，输入区不再提供模型切换。
6. **品牌化**。文案/About/manifest/UA 全部 AsterHub 化；图标是占位 SVG（渐变 A），待正式美术后重新生成 PNG/ICO/安装器图。

## 6. 环境与构建（Windows 实测）

1. Node 24（或 22.19+）；git 2.26+。
2. pnpm：`corepack enable` 会写 `C:\Program Files\nodejs` 需要管理员（EPERM）。解法：`corepack enable --install-directory "$HOME/.corepack-bin" pnpm`，然后每个终端 `export PATH="$HOME/.corepack-bin:$PATH"`。根构建脚本子进程会直接调 `pnpm`，PATH 必须挂 shim。
3. `pnpm install` → `pnpm run build`（首次构建约 3-5 分钟）。
4. 启动：`pnpm run start:desktop`（= apps/desktop 的 `dev.ts --skip-build`）。**不要用 `dev:desktop`**——它会重跑根构建。首次启动会下载约 37MB 运行时到 `apps/desktop/.desktop-build/downloads/`。
5. 跑通标志：日志出现 `dsh web: http://127.0.0.1:<port>/?token=...`；token→303+cookie→`/` 返回 200。
6. 调试端口：main=9229 / renderer=9222 / host=9230。端口被占会启动失败（报 address already in use），先清残留 Electron/Node 进程。
7. Windows 上 `TaskStop`/杀进程常留子进程树，重启前用 PowerShell 按 CommandLine 匹配清理。
8. lefthook pre-commit/pre-push 会跑 lint+typecheck，需要 pnpm 在 PATH 上，否则 push 被挡（exit 127）。
9. 已知环境红：`packages/preset/agent-presets/tests/discovery.spec.ts` 一条用例需要 symlink 权限（EPERM），Windows 无开发者模式时必红，非代码问题。

## 7. 已知问题：账户"服务不可用"（当前最高优先级）

**现象**：设置 → 账户，内容区显示"账户服务不可用"（由 `AccountSection` 在 `getAccountApi()` 返回 undefined 时的兜底 UI）。左上角头像菜单同理（api 不可用时不加载状态）。

**排查线索（按时间序）**：

1. 最初实现用 `inject: () => ({ api: ctx.remote.accountSub2api })` 传远程面，设置内容区渲染出 `<div data-slot-error="settings.section">` —— 这是 `SlotErrorBoundary`（`packages/client/ui-renderer/src/client/scoped-slots.tsx:417`）的崩溃占位，说明 **inject 工厂或组件渲染抛了异常**，且异常被边界吞掉（console 截获为空，疑似注册期一次性失败后进入"干涸"状态，不重复报）。
2. 改为模块级懒解析（`account-api.ts` 的 `setAccountApiResolver(() => ctx.remote.accountSub2api)`，组件经 `getAccountApi()` 读取，undefined 时渲染兜底 UI）后不再崩，但取值结果为 undefined → 说明 **`ctx.remote.accountSub2api` 在客户端不可用**。
3. 待查方向（按嫌疑排序）：
   a. **远程挂载时序**：`ui-settings-account` 的 apply 早于 `api-remotes` 完成对 `accountSub2apiRemote` 的 `$mount`，取值时命名空间尚未注册。懒解析已消除时序，但当前实现只在 apply 期 set 了一次 resolver（resolver 读取时才访问，理论上已规避）——若仍 undefined，则不是时序。
   b. **生成的 remote-client 与服务名不匹配**：宿主服务 `super(ctx, 'accountSub2api')`；生成产物 `lib/typert.remote-client.d.ts` 的调用键为 `accountSub2api/getStatus` 等（命名正确）。核对 `lib/typert.remote-client.js` 暴露的 contribution 的 `package` 字段与 `@deepseek-ai/dsh-account-sub2api/remote` 指向是否一致。
   c. **宿主服务未实例化**：检查 Host 日志中 `account-sub2api` 行是否成功挂载（组合文件 `- insert:` 块，`packages/bundle/web-app/cordis.patch.yml` 末尾）；Config 里 `groupId: z.any().default(6)` 可能不被 schemastery 接受为合法 config schema，尝试改成 `z.union([z.string(), z.number()]).default(6)`。
   d. **复现工具**：mock 网关脚本（Temp 下 `asterhub-mock-gateway-v2.mjs`）支持 `auth/login`、`keys` 列表/创建/删除、`user/profile`、`payment/orders`、`redeem-codes/redeem`；启动桌面时设 `ASTERHUB_AUTH_BASE_URL=http://127.0.0.1:8123/api/v1` + `ASTERHUB_MODEL_BASE_URL=http://127.0.0.1:8123/v1` 即可全流程自测（登录任意邮箱+非 wrong 密码，余额固定 42.5 USD）。请求日志在同目录 `asterhub-mock-requests.jsonl`。
4. 验证方法：修好后启动 → 设置 → 账户应显示登录表单；登录后应显示 user/42.5 USD；mock 日志应出现 `Bearer mock-token-*` 的 keys/user/profile 请求；再发一条会话消息确认模型调用链路（键已写入 `SUB2API_API_KEY` 引用）。
