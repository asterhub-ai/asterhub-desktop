# AsterHub Desktop 交接文档

[English](交接文档.md) | 中文

本文记录 DSH Desktop 当前产品契约与交接状态。精确行为以源码、测试和所链接的模块文档为准。

## 1. 产品边界

AsterHub 是由 Electron 桌面壳、本地 Node Host 和内置 Web 客户端组成的应用。DSH fork 在 `asterhub` 分支维护；上游仓库用于挑选修复，不决定产品组合。

Desktop Host 在任何 profile/home patch 装载前固定模型路由：provider 为 `sub2api`，model 为 `aster`，Base URL 为 `https://xapi.fans/v1`；账户控制面固定为 `https://xapi.fans/api/v1`。登录取得的模型 key 写入 Host credential record `asterhub-account/model-api-key`，不会从 `SUB2API_API_KEY`、`.env` 或进程环境读取，也不会返回给 Client。

Session 模型选择、旧 Session 状态、`settings.yaml`、Workflow 子任务参数、subagent 参数和 `llm/stream` 中间件均不能让内置 DSH 模型请求使用其他 provider/model 路由。适配器 profile 与 Base URL 由 application-owned Host route 重建。本机管理员和已安装的 Host 插件仍属于可信能力边界：应用路由锁不隔离恶意进程内代码，也不禁止这类代码自行发起网络请求。

## 2. 插件与 MCP 操作

应用“插件”页是单独的签名精选目录。Host 对原始 payload 字节验 Ed25519 签名，并检查有效期、单调修订号、条目标识、精确 package 版本和 registry integrity。安装请求绑定目录 revision 与全部签名包信息；Host 要求根 importer 直接解析到该精确版本，并在激活前核对所指 registry package 的 integrity。精选安装会禁用依赖脚本。初始目录为空；没有当前有效签名 payload 时，目录不可用。

用户另行授权对话通过任意来源管理插件与 MCP 生命周期。standard、PTC 和 Creator 预设开放现有 `plugin_manager` 工具，保留每次 Host 操作审批与依赖构建脚本审批。MCP 可通过包含 `@deepseek-ai/dsh-mcp-client` 的 DSH bundle 接入；随附 `adding-mcp-server` skill 说明 stdio 与 Streamable HTTP 的 bundle 配置及组合包启停/卸载流程。没有直接接受原始命令/URL 的独立 MCP 管理器。

Plugin Manager 阻止普通 bundle 生命周期操作改动模型、凭据和沙箱策略核心组合行。已安装 Host 插件仍以 Host 用户权限执行，不受工作区沙箱限制。

## 3. Desktop 更新和目录服务

`services/asterhub-catalog/` 是只读 Node/Docker/Nginx 部署脚手架，提供签名目录、electron-updater feed 文件和现有强制更新策略接口。策略路由当前只返回安全的“无需强制更新”。签名 starter 目录为空；验签公钥固定在 `apps/desktop-host/src/catalog-trust.ts`，Ed25519 私钥保存在仓库外的本机 AsterHub 签名密钥目录。

新构建的 Desktop 安装包会把 `https://asterhub.xapi.fans` 写入更新 feed 与策略请求 origin。现有发布器仍将 feed YAML、二进制和 blockmap 发布到腾讯 COS。Nginx 示例将 `/dsh-desk/feeds/` 和 `/dsh-desk/bin/` 只读代理到同一个 bucket；Node 服务处理元数据 API。已安装的旧版本仍使用其安装包内嵌的 feed URL。Cloudflare DNS 和德国主机服务尚未更改或部署，因此该公网域名还不是实际可用的 AsterHub release endpoint。

## 4. 当前工作树验证

已检查受影响的 Host/Client TypeScript 项目图。定向 Vitest 覆盖路由锁、账户 credential record、Session/Workflow/subagent、插件生命周期、精选目录验签/安装匹配、随附 preset skill 可见性及 Desktop feed 选择。服务端 Node 测试覆盖签名目录、fail-closed、no-force 策略、静态 feed 映射和路径穿越拒绝。Docker Compose 和正式签名打包的 Desktop 更新尚未在此环境验证。

## 5. 部署边界

公网启用前应检查 `asterhub.xapi.fans` 当前 Cloudflare DNS 记录，将其与德国主机现有 Nginx/TLS 路由核对，并保留现有 xapi.fans 服务。当前 `rover` 账户无法访问 Docker；本轮没有更改权限、使用 `sudo`、修改 Cloudflare/DNS/证书、SSH 部署或启动服务。部署服务和启用 DNS 仍需要合适的主机权限，并在执行时再次取得最终确认。

不要把准备好的脚手架描述为已上线服务。在配置源已有经过验证的签名平台 feed metadata 与不可变签名产物之前，不要发布 Desktop 更新。
