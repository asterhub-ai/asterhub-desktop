# AsterHub Desktop 更新检查与 Windows 发布设计

[English](2026-10-04-desktop-settings-updater-design.md) | 中文

- **状态：** 用户已批准实施
- **范围：** `AsterHub-reference` Desktop 更新 UI 和一次 Windows x64 生产更新发布
- **发布目标：** `0.2.0-rc.3`，Windows x64 标准签名安装器

## 目标

在常规设置的已安装版本旁增加手动**检查更新**操作，并向现有 AsterHub electron-updater 源发布签名的 Windows x64 安装器，供 Desktop 客户端下载。

## 当前实现

`packages/client/ui-settings-general` 在 `CurrentVersionRow` 中展示编译时版本。`DesktopUpdateSource` 和可选 Electron preload 提供状态及 `open()`。原生应用菜单调用 `openUpdatePrompt(true)`，当前 preload 的 `updates.open` 则走非手动路径。主进程负责 `DesktopUpdateCoordinator`、候选版本选择、下载、安装更新、活动任务检查和重启交接；渲染进程不能提供版本或 URL。

现有手动菜单路径检查固定 Nightly 源，展示可用版本，在用户同意后下载，再调用更新器安装流程。下载完成后，主进程还会展示普通的安装并重启确认；存在活动工作时，改为展示任务中断确认。

Desktop 发布构建器已经生成平台更新元数据和二进制文件。上传器先向生产 COS 写入带版本的 Windows 安装器和 blockmap 对象，再写入 `nightly.yml`。`asterhub.xapi.fans` 是固定生产源；公开 Nginx 层按文档作为 COS 的只读代理。当前线上 Windows Nightly 源返回 HTTP 404。

## 设置交互

在常规设置的版本旁增加本地化的**检查更新**按钮。仅在存在 Desktop preload 更新 API 时展示此按钮；普通浏览器用户仍只看到版本。保留现有版本文本、行的归属、设置布局和按钮样式规范。

增加专用于手动更新检查的 preload/IPC 操作。它必须验证发送者是主产品文档，再委派给主进程手动提示。渲染进程不提供更新 URL、版本或安装授权。

检查没有发现新版时，展示现有本地化的当前版本结果。存在新版时，一次明确的**下载并安装**确认授权下载已检查的精确候选版本，并在下载成功后进入安装。确认前不得下载或安装。下载失败允许重试，不进入安装。

准备安装时若存在活动工作，保留单独、明确的任务中断确认。用户拒绝、任务状态未知、出现新的活动工作或 Host 未正常关闭时，拒绝安装。没有工作需要中断时，最初的更新确认授权安装和重启，不再询问第二次。自动后台检查保持静默，绝不下载或安装。现有更新徽标状态保持不变；应用菜单和设置页的手动检查共用经确认的下载并安装流程。

## Windows 发布与服务器流程

保留现有签名打包器和生产 COS 上传器。不为 Node 目录服务增加上传路由，也不在德国主机存储发布凭据。

通过仓库发布流程同时将根目录和 Desktop 产品版本提升到 `0.2.0-rc.3`。从当前源码构建 Windows x64 标准签名安装器，使用现有 `apps/desktop/.env.windows` 配置，不展示或复制凭据值。生产打包命令必须使用产品版本，不传入 `--build-version`。

在生产上传前，验证签名完成记录、包版本、目标、公开源、文件大小、SHA-512、安装器、blockmap 和 `nightly.yml`。向用户展示精确生产 COS key、字节数和 SHA-512，并在首次写入前获得即时确认。然后使用现有上传器发布 Windows x64 Nightly 源及带版本的产物。本次预发布不要求固定 `latest` 安装器别名，因此不要覆盖它。

上传后，通过 `https://asterhub.xapi.fans` 获取源和每个产物 URL，将版本与 SHA-512 和签名打包记录比较，并验证源可访问。该源目前返回 404。若最终公开路由仍返回 404，在修改生产 Nginx 或 Cloudflare 配置前停止；报告精确缺失路由，并为基础设施修改另行取得确认。

## 验证

- 增加 Client 回归测试，验证设置版本行展示 Desktop 专属操作，并在纯浏览器环境中省略它。
- 为从该操作发起的手动更新增加原生流程覆盖：没有更新、可用更新同意、取消同意、下载失败、同意后的自动安装交接、活动任务确认拒绝，以及不发生静默安装。
- 运行全部受影响的 Client 与 Desktop 测试文件、Host 和 Client TypeScript 项目图，以及 `corepack pnpm run build:official`。
- 前置条件允许时，运行仓库的真实 Windows 本地更新器验收。
- 仅在本地打包预检成功后构建标准签名 Windows x64 发布。上传前确认精确生产对象；上传后验证每个公开响应和哈希。

## 风险与约束

- 更新包是对外可见的签名 Windows 安装器。不得将未签名、陈旧或不完整产物视为发布。
- 安装可能停止活动 Agent 和子工作。适用时仍需单独确认任务中断；任务状态不可用时拒绝安装。
- 当前生产 Windows 源返回 404；单独上传不足以证明公开更新路由可用。
- `.env.windows` 已存在于本机，值保持私密。缺少签名或 COS 输入必须由预检报告，不得编造。
- 用户此前已确认的登录、模型和账号测试结果仍视为完成；本次工作不重复它们。
