# AsterHub 项目架构盘点与收拢建议

> 当前状态、用户验收缺口和接手顺序见[项目现状交接](交接文档.md)与[离线状态看板](index.html)。本文保留 2026-10-22 源码审计参考，不代表已实施的重构结果，也不替代各模块契约。产品目标由用户明确：以 DSH 为基础构建专用 Agent，避免长期偏离上游。

## 摘要

AsterHub 仍以 DSH 为执行骨架，新增能力大量通过 Cordis 插件接入，并未重新实现 Agent 主循环。当前主要风险不是缺少插件入口，而是产品默认配置进入共享组合、项目存储实现被多个通用消费者直接依赖、模型部署策略需要维护公共 LLM 层改动，以及 Session 格式开始独立演进。

建议保留已有功能，优先收拢产品组合与依赖边界；复核持久化版本升级理由和 Office 权限边界，再决定重构范围。不要以架构整理为由放松模型路由、账户鉴权、文件权限或历史数据保护。

## 目标架构与取舍原则

建议采用“DSH 通用基座 + AsterHub 功能插件 + 产品组合 + 桌面发行”的分层。DSH 的插件既可以随产品内置，也可以独立安装；同仓开发和随应用打包，不意味着没有插件化。架构判断重点是依赖、生命周期、配置归属和替换能力，而非包的位置。

| 层次 | 责任 | 取舍原则 |
|---|---|---|
| DSH 基座 | Agent、会话、工具执行、权限、持久化、SDK 和通用扩展机制 | 尽量沿用上游；必要改动保持小而通用 |
| 功能插件 | 记忆、领域工具、自动化、能力 provider、功能 UI | 业务逻辑和资源由功能拥有，显式声明依赖与清理 |
| 产品组合 | 默认插件、账户路由、提示词、预设、技能和产品策略 | AsterHub 专属默认值通过独立 bundle/profile/overlay 提供 |
| 桌面发行 | Electron、安装更新、系统能力、运行时资源和品牌 | 保留合理宿主职责，不混入 Agent 核心业务 |

优先使用现有扩展点。扩展点不足时，先设计通用接口，再由业务插件实现；不得通过复制 Agent 循环制造形式上的插件化。可选功能移除后基础组合应能运行，必要依赖则应明确声明。模型供应商、接入地址及凭据仍由应用控制，用户只选择当前账户目录中可用的模型。

项目架构机制以 [DSH 架构](../docs/architecture.md) 为准；本节是收拢建议，不声明这些边界已经全部实现。

## 已核实的耦合与风险

### 共享组合承载产品默认值

[共享 base](../packages/bundle/base/cordis.patch.yml) 设置了 `sub2api`、账户凭据记录、部署锁及私有搜索默认值；[共享 Web 组合](../packages/bundle/web-app/cordis.patch.yml) 挂载 Anima、项目存储和项目附件策略。即使所有条目都是插件，这些配置仍扩大了通用组合与产品策略的交集。

建议把 AsterHub 专属默认值迁到自己的 bundle/profile/overlay，参考已有 [Desktop-only bundle](../packages/bundle/asterhub-desktop-native/cordis.patch.yml)。迁移必须保持现有账户模型目录、固定供应商路由和凭据约束，不能退化为只隐藏 UI。

### 项目存储实现依赖扩散

[Workspace](../packages/workspace/workspace/src/index.ts) 删除会话时直接调用 `projectStorage`；[本地附件存储](../packages/attachment/attachment-local/src/index.ts) 直接解析项目归属；[pi-ai 适配器](../packages/llm/llm-pi-ai/src/index.ts) 根据项目存储是否存在决定附件作用域。会话控制器也承担作用域传递。

这些处理服务于真实的数据归属与可迁移需求，不能直接删除。建议设计窄接口承载会话位置、附件归属与访问解析，由 project-storage 提供实现，避免模型适配器了解具体存储组织。验收应覆盖迁移项目、跨会话附件拒绝、缺失项目和会话删除。

### 模型部署策略改变公共 LLM 行为

[桌面 Host](../apps/desktop-host/src/index.ts) 提供 `applicationModelRoute`；[公共 LLM 服务](../packages/llm/llm/src/index.ts) 在调用执行路径实施路由限制，并约束 provider 列举、模型发现和解析；[pi-ai 插件](../packages/llm/llm-pi-ai/src/index.ts) 同时处理部署锁定配置。

执行层强制约束是必要的，产品策略不能仅靠客户端选择器保护。这部分已有泛化接口，不应全部视为业务硬编码；但公共 API 和调用路径的差异需要长期跟随上游。建议评估更窄的部署策略接口或可回馈上游的通用实现，迁移前覆盖会话、辅助请求、子代理、Workflow 和直接调用路径。

### Session V5 的升级理由需要复核

[Session 类型规则](../packages/core/session/src/types.ts) 规定普通事件扩展不升级整体格式，由事件级兼容机制处理；本地版本却已从上游 V4 变为 V5。[V4→V5 迁移](../packages/session/session-format-v4-to-v5/src/migration.ts) 修改版本号并原样传递事件，物理编码继续使用 V4 codec。

Anima 的辅助请求和结果确实需要持久记录，事件白名单与类型声明不能随意删除。但仅新增普通持久事件，尚不足以解释整体版本升级。[持久化变更记录](../docs/persistence-changes/2026-10-18-anima-session-v5.md) 中同批其他事件是否存在结构或语义不兼容，仍需逐项核实。

本次结论是“升级理由存在未解释的规则张力”，不是已证明 V5 错误。不得把版本常量直接改回 V4、删除迁移或重写已提交的历史世代；已有 V5 数据必须保留。后续需先证明旧 reader 具体在哪种新日志上无法正确恢复，再确定安全兼容方案。

### 产品身份进入通用默认行为

[system-prompt](../packages/core/system-prompt/src/index.ts) 的默认身份文本直接使用 AsterHub；[LLM attribution](../packages/llm/llm/src/attribution.ts) 的默认请求归属也使用产品身份。建议由产品配置或提示词贡献提供具体身份，通用模块保留组装与执行能力。此类调整相对低风险，但仍需保持模型可见输出并更新对应验证。

### Office 权限等价性尚未验证

[GenOffice 桥接](../services/asterhub-catalog/packages/genoffice-cli/index.mjs) 通过 MCP stdio 启动 CLI、设置会话工作目录，并注册工具；`GENOFFICE_ALLOWED_ROOTS` 仅在环境已设置时透传。工作目录和 `realpath` 解析不等于文件访问授权。

本次未完整检查分发资源中的 CLI 路径限制、通用 MCP 工具审批及子进程约束，因此不能声称已发现越权漏洞，也不能声称它与 DSH 文件沙箱等价。应另行验证工作区外读写、符号链接、只读策略、审批拒绝和取消场景。

### 合理宿主职责应保留

窗口、安装升级、浏览器主进程传输、系统凭据加密以及 Java/Neo4j/语音模型资源分发属于产品宿主或发行职责。不要求所有职责都进入 Agent 插件。目标是减少不必要的基座差异，不是以搬目录代替解耦，也不是取消既有功能。

## 建议优先级与验收条件

以下均为待实施建议；本次没有授权或执行产品重构。

| 优先级 | 工作项 | 完成条件 |
|---|---|---|
| P0 | 复核 Session V5 与已有数据兼容 | 逐项说明格式升级理由；形成保留历史世代和现有 V5 数据的兼容方案 |
| P0 | 验证 Office 文件权限和审批 | 用允许与拒绝用例证明实际路径边界，不以 cwd 代替授权 |
| P1 | 收拢 AsterHub 产品组合 | 产品默认值有独立拥有者；通用组合不隐含私有服务；桌面行为与约束不退化 |
| P1 | 收拢项目存储和附件依赖 | 通用消费者依赖窄接口，项目可迁移性与附件归属测试保持通过 |
| P1 | 缩小模型部署策略差异 | 所有调用路径仍受执行层约束；不开放供应商、地址或密钥修改 |
| P2 | 外置品牌默认值 | 产品身份由组合提供，通用模块不固定品牌 |
| P2 | 整理凭据与精选插件边界 | 明确文件格式、安装信任、资源分发和升级的责任归属 |
| 持续 | 维护基座差异台账 | 每项区分上游回移、通用修复、必要扩展和业务定制，附适配与验证要求 |

先建立逐项差异台账并确认方案，再分批重构。每批只处理一个可验证边界；不得顺手更换记忆数据库、放松权限或修改发布策略。用户既有 Neo4j、本地记忆、账户积分和受控模型接入要求继续保留。
