### 当前启动与数据位置

安装型应用的 Electron Main 管窗口、托盘、更新与恢复；由 `apps/desktop/src/host-process.ts` 启动私有 Desktop Host，Host 通过受支持的 `dsh` profile runner 装配服务，再由本地渲染器连接。`apps/desktop-host/src/index.ts` 负责产品路由与信任根等启动约束。Windows portable 目录的小启动器与 `AsterHub.Runtime.exe` 是另一交付形态，不是所有 NSIS 安装的通用结构。

- 默认全局数据目录是 `~/.asterhub`，由 `packages/util/home-paths/src/index.ts` 定义；`DSH_HOME` 可显式覆盖。旧 `~/.dsh` 的迁移按既有 home migration 处理，不能再把它写成当前默认路径。
- 项目私有数据在工程 `.aster/`：`project.json`、`sessions/`、`attachments/v1/`。全局 locator 在 `~/.asterhub/locator.json`。打开复制或移动项目先只读 inspect 并确认；历史 header 不改写，运行 cwd 跟随当前绑定。
- 当前 Session 格式为 V5；保留已提交历史世代与 V4 迁移，不回退格式或重写前代，SQLite schema 版本同样不回退。项目 `.aster/` 的 Git 隐私排除、已跟踪私有数据的拒绝/警告和取消时无写入约束必须保留；不要擅自删除、取消跟踪或清空真实用户目录。

## 5. 已知问题与验收缺口

### 5.1 设置"当前版本"取错来源（源码已修复验证）

状态见看板 T01。实现要点：`apps/desktop/src/ipc.ts` 和 `preload-app.ts` 通过 `DESKTOP_IPC.appVersion` 向客户端 `dshDesktop` 载体同步注入由 `app.getVersion()` 取得的实际安装版本；`packages/client/ui-settings-general/src/client/CurrentVersionRow.tsx` 优先渲染注入的 `installedVersion`，无载体的通用 Web 渲染器保持回退至编译时 `process.env.DSH_CLIENT_VERSION`。相关组件渲染和槽位注入测试（`components.client.spec.tsx`、`apply.client.spec.ts`、`preload-app.spec.ts`）共 55 项全部通过。

### 5.2 旧明文凭据阻断升级启动（源码已修复，实机验证未做）

用户先前提供的 Host crash 日志明确为 `.asterhub/.credentials.yaml is not encrypted`。现已在 `packages/credentials/credentials-local/src/index.ts` 实现受控原子迁移，并在 `packages/bundle/base/cordis.patch.yml` 中仅为 Desktop profile 启用 `migratePlaintext`（其他 profile 及通用加密存储保持严格 fail-closed 拒绝明文）：
1. **原子锁与重读**：在 `withFileLock` 保护下重读磁盘内容，若并发进程已发布密文则直接解密加载，不重复写入；
2. **严格预校验**：解析并校验平铺格式或 version-1 格式，格式未知或损坏时拒绝启动且绝不改动原文件；
3. **加密往返自检**：调用 OS cipher 加密后立即尝试解密比对，确保内容逐字节一致才允许提交；
4. **原子落盘与防降级**：通过 `writeFileAtomic` 原子写入 0600 密文；写入失败原明文完好无损。文件变更监听（watcher）保持严格调用 `decodeDocument`，拒绝运行时将密文替换为明文并保留内存中有效快照。
5. **验证状态**：`encrypted.spec.ts`、`migration.spec.ts`、`local.spec.ts` 共 72 项测试全部通过（1 跳过，0 失败）。当前已打包的 r11 安装包生成于此修复之前，保留旧数据的真实桌面启动仍须在含修复候选上实机验收（v4 候选已含此修复并通过包级探针，实机复验未做）。
